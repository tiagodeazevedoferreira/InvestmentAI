# Task 051 — XGBoost OOS economic sensitivity

**Status:** IN PROGRESS

## Objective

Measure the economic sensitivity of the already-generated XGBoost OOS probability artifact across a fixed threshold grid and transaction-cost scenarios without retraining, threshold selection, or model promotion.

## Scope

Controlled B3 sample:
- PETR4
- VALE3
- ITUB4
- 2021-09-15 through 2026-09-15
- horizon 5
- train size 500
- test size 100
- step 100
- initial cash 100,000
- thresholds: 0.50, 0.55, 0.60, 0.65, 0.70, 0.75
- cost scenarios: zero cost and 0.1% commission + 5 bps slippage

The exact shared OOS artifacts generated by the existing validation pipeline are reused. No model is retrained and no alternative OOS prediction set is generated.

## Required outputs

For each symbol, threshold and cost scenario:
- final cash;
- strategy return;
- maximum drawdown;
- trade count;
- total commission;
- total slippage;
- final position;
- OOS interval and row/fold counts;
- incremental return and cash impact versus zero cost at the same threshold.

## Interpretation boundary

The threshold grid is a descriptive sensitivity analysis, not an optimization procedure. The report must preserve every configured threshold and must not select, rank, promote or automatically replace a threshold based on observed OOS performance.

Cost comparisons are paired at the same threshold so economic friction can be separated from threshold sensitivity. Results remain research-only.

## Controls

- Reuse the existing shared OOS artifact and provenance validation.
- Reuse `backtest_xgboost_oos_run()` for every replay.
- Keep XGBoost parameters unchanged.
- Keep the OOS timestamps unchanged.
- Do not regenerate OOS predictions per threshold.
- Do not modify execution policy, risk gates or broker controls.
- No MT5/DOTO execution or financial transaction.

## Acceptance criteria

- [ ] Fixed threshold grid is validated and deterministic.
- [ ] One shared OOS artifact is reused across all threshold/cost combinations for each symbol.
- [ ] Both zero-cost and combined-cost replays are reported for every threshold.
- [ ] Deterministic contract tests pass.
- [ ] Real-data sensitivity report completes for PETR4, VALE3 and ITUB4.
- [ ] Backend suite and compilation pass.
- [ ] Workflow uploads the sensitivity report with the existing OOS validation artifacts.
- [ ] No threshold is automatically selected or promoted.

## Next stage

Use the resulting sensitivity surface together with probability calibration, fold stability and cost attribution to determine whether the next research experiment should focus on calibration, signal persistence/turnover, feature/model changes, or additional economic validation. Any subsequent threshold experiment must remain separated from the same-sample evaluation evidence used for this diagnostic report.
